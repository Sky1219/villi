<objective>
Make the guideline corpus searchable the way the demo needs it: embed chunks once with Voyage `voyage-4-lite` (1024 dims) through an idempotent, hash-gated `embed:run`, and search with `guidelines.search`, which tries the vector index once and silently degrades to the Convex full-text index on any failure.

Purpose: Phase 2's `search_guidelines` tool is a thin wrapper over this. The builder's Voyage key is a no-card trial with low, undocumented limits (D-16), so the text path must carry the demo on its own.
Output: `convex/lib/embed.ts`, `convex/embed.ts`, `convex/guidelines.ts`, and their tests.
</objective>

## Phase Goal

The app runs locally and on a real phone over HTTPS, with the complete schema, a cited guideline corpus that can be searched, a synthetic community seed, and a usable profile without onboarding (ROADMAP Phase 1, verbatim; not reframed as a user story, see Plan 01).

<assumption_delta_decision>
Signal: pluralization of "fallback" ("still returns results through the full-text fallback when the embedding call fails").
Primary noun: the guideline chunk identity, `chunkId = sourceId#locator` (D-11), shared by both search paths.
Decision: promote. The chunkId is the single identity of a chunk everywhere (citations, search results, seed upserts, diagram lookups). The full-text fallback is a second retrieval path over the same rows, not a second identity model; neither path ever returns a Convex `_id` as the identity.
Rationale: a stable string id lets Phase 2 validate `[G:<chunkId>]` citations the same way regardless of which path retrieved them, and survives re-seeding.
Invariant test: `convex/guidelines.test.ts` asserts that for the same fixture chunk both paths return identical result keys and the same chunkId.
</assumption_delta_decision>
